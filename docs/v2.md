# ACP v2 transport (experimental)

This branch adds an opt-in ACP **v2** transport next to the stable v1 one. The
goal is the v2 capability the v1 protocol lacks: telling the client that work
continues after a prompt response (autonomous goal rounds), so the editor keeps
showing the thread as running instead of marking it finished.

## Switch

```bash
DSH_ACP_V2=1   # on the ACP profile process (Zed spawns it with this env)
```

Without the variable everything is byte-for-byte the v1 transport; the v1 path
is unchanged and keeps the existing install usable.

## How it works

The proxy (`src/v2/proxy.ts`) owns stdio and mounts the existing v1 bridge on an
in-memory duplex pair. For v2 clients it:

- answers `initialize` with `protocolVersion: 2`, `info`/`capabilities` and
  `authMethods`, while the bridge still sees a v1 initialize;
- maps `session/resume` onto the bridge's `session/load` and holds the response
  until the replay finished (`_dsh/replay_complete`), because v2 orders replay
  before the resume response;
- maps `session/prompt` to a v2 response carrying `messageId` and moves the stop
  reason into the idle `state_update`;
- translates v1 `tool_call` → v2 `tool_call_update`, `plan` → `plan_update`,
  drops v1 mode updates (v2 uses config options), and keeps `messageId` on
  content chunks;
- turns the bridge's `_dsh/goal_activity` marker into `state_update`
  `running` / `idle`, so a long-running goal keeps the thread alive after the
  prompt returned;
- rejects v1-only client methods (`fs/*`, `terminal/*`) that v2 removed.

Custom `_dsh/*` markers never reach the client.

## Covered in tests

`test/v2-proxy.test.ts` (unit, fake v1 engine):

- initialize fields, v1 passthrough;
- prompt → running state, translated tool call, idle with stop reason,
  `messageId` response;
- resume replay ordering (replay before response, including the case where the
  replay finishes first);
- goal activity keeps the client running.

`test/v2-e2e.test.ts` (real standalone server, skipped when the checkout lacks
the DSH harness packages) boots `src/bin.ts` with `DSH_ACP_V2=1` and checks the
v2 handshake, `session/new`, a `/status` prompt and the state updates.

Manual verification against a real profile (a cloned `acpv2` profile pointing at
the v2 tarball):

- `initialize` v2 → `protocolVersion: 2`, `info`, no `agentInfo`;
- `session/new` → session id;
- `/status` prompt → `messageId`, `running` then `idle/end_turn`, no `_dsh/*`
  leak;
- `session/resume` of a large session → 1266 replayed updates;
- the same build without `DSH_ACP_V2` still serves v1 clients unchanged.

## Known limitations

- The v2 schema is still a draft upstream (`@agentclientprotocol/sdk`
  `experimental/v2`); field shapes may change between SDK releases.
- `session/fork`, subagents, elicitation and auth methods are passed through
  with minimal mapping; they are not covered by the v2 tests yet.
- The proxy tracks one live session per connection when emitting state updates
  (matching a single editor thread per agent process).
